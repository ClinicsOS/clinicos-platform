# Dermatology & Aesthetics — 3D body model assets

This folder is where the **final Male and Female 3D models** of the clinical map go.

## Current status (read this first)

**`male.glb` and `female.glb` are delivered (visual model v3 — superficial musculoskeletal atlas style, `modelVersion: "derm-human-v3"`).**

They are **procedurally generated by our own code** (`scripts/derm-human/`: signed-distance-field sculpting → superficial muscle layer
(≈140 muscle / tendon / bone territories that sculpt bellies + grooves and drive atlas colours) → surface nets → colour-guided
simplification → baked ambient occlusion → clinical hit layer → GLB). **No third-party / artist asset, scan,
texture or downloaded model was used.** They are a *stylised superficial-anatomy* human (muscle red-brown, pale tendons, ivory bone landmarks, pale scalp) — **not
photorealistic**, **not artist-made**, and **without muscle-fibre detail**. A professional artist-made pair of GLBs following the contract below would still improve the face, hands and
overall finish materially; it can replace these two files with no change to any code, API or stored record.

* Visible skin = mesh `skin` (vertex-coloured, smooth normals). The clinical hit layer = hidden helper meshes `hit_<registry id>`
  (one per region, index-only, sharing the skin's vertex buffer). Both come from the same generated surface, so they align exactly.
* If a file is missing / corrupt / rejected by the contract, the app falls back to the **emergency procedural body**
  (`components/derm/engine/bodyBuilder.ts`) and says so in the UI. That body is never the normal view.
* `DERM_HUMAN_MODEL_VERSION = "2"` (`src/lib/derm/modelVersion.ts`) is visual / mapping metadata only. Nothing clinical is
  migrated when the artwork changes: every record points at the stable registry ids.

To regenerate: see `scripts/derm-human/README.md`.

## What the artist / vendor must deliver

Two files, one per model:

| File | Purpose |
|---|---|
| `male.glb` | Male visual model |
| `female.glb` | Female visual model |

plus the region mapping written into `manifest.json` (below). The two models do **not** need identical topology; they
only need to expose the same region ids.

### Format & technical requirements

- **glTF 2.0 binary (`.glb`)**, PBR (metallic-roughness) materials.
- **Compression: Meshopt is supported** (`gltfpack -cc` / `gltf-transform meshopt`) — the decoder ships inside three.js,
  nothing extra to host. **Draco and KTX2/Basis are NOT enabled** (they need separately hosted decoder files); ask the
  vendor for uncompressed or Meshopt output, with textures as plain PNG/JPEG (max 2048 px; 1024 px is plenty for a matte
  clinical skin).
- **Units: metres. Origin: on the floor between the feet** (lowest point at `y = 0`, tolerance 8 cm). Height between
  0.5 m and 2.6 m. The loader rejects an asset outside these ranges (typical mistake: exported in centimetres).
- **Canonical axes (this is critical): `+X` = the patient's LEFT, `+Y` = up, `+Z` = the direction the patient faces
  (anterior).** The patient stands in a neutral anatomical pose, arms slightly away from the body, palms forward.
  - The loader **rejects a mirrored asset**: every `left_*` region must have its centre at `x > 0` and every
    `right_*` region at `x < 0`. A mirrored file would silently swap the patient's left and right — the one error the
    system must never allow.
- Closed, outward-facing, smooth-shaded skin. Roughly 30k–120k triangles per model is a good target (must stay smooth on
  a mid-range phone; the app lowers the pixel ratio and skips environment lighting on phones automatically). Keep each
  file under ~15 MB.
- **Material: a clean matte / semi-matte clinical surface** — roughness 0.7–0.85, no clearcoat, no strong specular, no
  metallic, no visible pores or wax/plastic sheen. The app supplies the studio lighting; do not bake lighting in.
- **Scalp must be exposed skin.** Do not deliver a model whose scalp is covered by opaque hair geometry. Hair is only
  acceptable as *decoration* (see `decorMeshes`); the eight scalp regions must exist as real skin surfaces underneath.
- No lights, cameras or animation are needed.

### Region meshes

Each registry region below needs **one or more meshes** that cover exactly that part of the skin (the region's
surface). They are used for the hover/selection highlight and for picking, so:

- Regions of one model must **not overlap** each other, and should tile the body without holes where clinically
  sensible (small gaps simply are not selectable).
- The mesh may be a **separate copy** of the skin triangles (a hidden helper mesh) or the visible skin split per region.
  Either is fine — see `skinMeshes`.
- Left/right pairs are separate regions (`left_cheek`, `right_cheek`). **Never** use gendered ids.
- Regions that the model genuinely does not have can be omitted: the app reports them as "not available on this 3D
  model" and keeps them selectable from the region list. Nothing crashes.

### Decorative meshes (hair, lashes…)

Anything that is drawn but is not skin (hair, eyelashes, brows as geometry, jewellery) goes in `decorMeshes`. It is
displayed, but it **never blocks picking**: clicking through hair still selects the scalp region under it. A mesh cannot
be both a region surface and decoration.

### Versioning

`modelVersion` (the shipped files use `"derm-human-v3"`) identifies the artwork only. It is **never** part of a region id and never stored
in a clinical record. A future `derm-human-v4` maps to the same registry ids, so all existing history stays valid.

### Mesh names are private

**A mesh name is never a clinical identity.** Only the registry ids below are ever stored or sent to the API. Name your
meshes however your pipeline likes (`Skin_Cheek_L`, `Mesh.042`, …) and translate them in `manifest.json`:

```json
{
  "version": 1,
  "models": {
    "male": {
      "file": "male.glb",
      "modelVersion": "derm-human-v1",
      "skinMeshes": ["Body_Skin", "Hair_Male"],
      "decorMeshes": ["Hair_Male"],
      "regions": {
        "forehead":    ["Region_Forehead"],
        "left_cheek":  ["Region_Cheek_L"],
        "right_cheek": ["Region_Cheek_R"],
        "left_forearm": ["Region_Forearm_L_Upper", "Region_Forearm_L_Lower"]
      },
      "landmarks": { "head": [0, 1.66, 0.01], "headRadius": 0.14, "neckBase": [0, 1.5, 0] }
    },
    "female": { "file": "female.glb", "skinMeshes": ["Body_Skin"], "regions": { } }
  }
}
```

- `file` — path relative to `manifest.json`. `null` = no asset yet → development mannequin.
- `modelVersion` — optional artwork version label (letters, digits, `.`, `_`, `-`).
- `decorMeshes` — optional; visible meshes that never block picking (hair etc.).
- `skinMeshes` — the meshes to **display**. Every mesh *not* listed is hidden (use this for invisible region helper
  meshes). If omitted / empty, **all** meshes are shown.
- `regions` — `registryRegionId → [meshName, ...]`. An unknown region id makes the whole manifest invalid (the app falls
  back to the development model and says so).
- `landmarks` (optional) — head centre, head radius and neck base in metres, used to frame the Face / Scalp views. If
  omitted they are estimated from the bounding box, which is usually good enough for a first integration.

## Validation and fallback behaviour

`assetLoader.ts` validates every asset. If anything fails, the app **falls back to the development model** and shows
*"The 3D model file could not be used — showing the development preview instead"* — the clinical map keeps working.
An asset is rejected when: the manifest is invalid, a mapped mesh is missing from the file, a region has no triangles,
a mesh is both a region and decoration,
the height is outside 0.5–2.6 m, the origin is not on the floor, or the asset is mirrored (left/right swapped).

## How to test a delivered model

1. Put `male.glb` / `female.glb` next to `manifest.json` and fill in the manifest.
2. Open a patient of a *Dermatology & Aesthetics* clinic → **Clinical Map**.
3. The "Development preview model" caption disappears when the GLB is in use.
4. Scalp view → **Top** / Front / Back / Left / Right presets: every one of the eight scalp regions must be selectable, also
   when the model has hair.
5. Click the **patient's left** cheek from the front: the highlighted region must be on the **right of the screen** and
   be labelled *Left Cheek*. Repeat from the back and from both sides. Check every region, and the Face / Scalp views.
6. Switch Male ⇄ Female: a selected region, history badges and marks must stay in the same anatomical place.
